# 0.6.0 发布方案（存档）

> 2026-10-27 定稿并完成。决策过程见会话；本篇为结论存档。

## 范围（全部已完成）

1. **包拆分**：官方 starter 命名规范（`{name}-spring-boot-starter`），按角色拆为
   client/server 两个 starter + 两个 MVC 装配包 + spring-common（TxAwareDataSources）；
   统一包（linkora-spring / linkora-spring-boot-starter）废弃
2. **传输加密**（默认开，与认证解耦）：AES-256-GCM，`Base64(IV+CT+Tag)`，
   信封 `enc:A256GCM:k1`（keyId 轮换位预留）；密钥独立配置（根级
   `linkora.payload-cipher-key`，带外分发，与认证正交）；上下行自动，业务零代码
3. **大 payload gzip**：>64KB 上行自动压缩，签名覆盖压缩后字节，服务端验签后解压
4. **数据同步工具**：client 内置 `com.linkora.client.sync`（快照表进客户端 schema v3，
   SPI default 方法兼容自定义实现）；面向"业务系统不改造"的旁挂同步场景
5. **认证扩展**：token 模式（TokenValidator 回调宿主）+ 客户端 TokenProvider SPI
6. **示例重构**：4 应用全功能（殡葬集团业务场景），sync 融入 boot-client

## 已否决的备选（记录避免重议）

- RSA 混合加密：预共享通道已存在（部署配置分发），RSA 无安全增益、+256B/条
- H2 作为测试基座：与生产引擎（SQLite）不同源，已彻底移除
- 客户端与服务端共用一个 jar：classpath 污染，业界（Kafka/RocketMQ/ActiveMQ）均拆分
- Redis 幂等去重：双写不一致，DB 唯一键 + SDK 分发层去重更正确
- 内置 IdempotentConsumer：SDK 分发层已去重，常规场景属过度设计
