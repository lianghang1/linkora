# 0.5.0 存储统一 + Spring-only 重构方案（定稿）

## 定位

- 仅支持 **Spring MVC(war → Tomcat)** 与 **Spring Boot(内嵌 Tomcat)** 宿主，写入 compatibility 文档
- **硬约束：全程 JDK 8 语法**（项目 source/target 1.8：无 var / switch 表达式 / text block / List.of）
- 引擎统一 **SQLite**；性能论证：日 500 条消息 ≈ 0.006 条/秒，SQLite WAL(NORMAL) 能力 ~10,000 写/秒、每条消息约 5 次写，占用率 <1%，不做压测，开发后按日均量冒烟

## 统一存储模型（两端能力对等、配置对称）

| 能力 | 服务端 | 客户端 | 动作 |
|---|---|---|---|
| `store=sqlite` 内嵌文件（**默认**，`db-path` 可配） | 补 | 已有 | 服务端新增内嵌模式 |
| `store=datasource` 复用宿主库 | 已有 | 补 | 客户端新增内置 `JdbcClientStore` |
| publish 随业务 `@Transactional` 原子提交 | 已有（server.publish） | 补（事务感知连接） | |
| autoMigrate | 已有（lk_*） | 补（lk_client_* 三表） | |
| 启动模式提示日志 | 补 | 补 | |

配置面（对称）：

```yaml
linkora:
  server:
    store: sqlite            # sqlite | datasource
    db-path: ./linkora/linkora-server.db
  client:
    store: sqlite            # sqlite | datasource
    db-path: ./linkora/linkora-client.db
```

内嵌模式统一 PRAGMA：`journal_mode=WAL`、`busy_timeout=5000`、`synchronous=NORMAL`；
datasource 模式连接走事务感知包装（加入宿主 @Transactional），不由 SDK 改宿主库 PRAGMA。

## 共用存储基建（复用代码，能力对等的落点）

| 组件 | 位置 | 职责 |
|---|---|---|
| `EmbeddedSqliteDatabase` | core | 内嵌 SQLite 打开/PRAGMA/路径，两端共用 |
| `SchemaMigrator` | core | 版本化迁移执行器（泛化自 JdbcServerSchema），lk_* 与 lk_client_* 共用 |
| `TxAwareDataSources` | spring | 事务感知 DataSource 包装，两端 publish 同事务共用 |
| `JdbcClientStore` | core/storage/client/jdbc | 客户端 JDBC 实现（outbox/inbox/meta/顺序键），与服务端仓储共享方言约定 |

## 重构清单

删除：examples/plain-java-server、plain-java-client、spring-tx-server、tx-client；
Jetty 产品级依赖（servlet API 保留，MVC war 装配需要）；文档中非 Spring 接入路径。
保留但降为内部设施：linkora-testkit（挪出 examples）、Server/Client Builder API（装配器内核）。

## 全套示例（4 独立应用 × 2 存储模式）

```
examples/
├── boot-server/   Spring Boot(内嵌 Tomcat)：服务端 + admin-console
├── boot-client/   Spring Boot：客户端嵌入业务服务（订单表 + publish 同事务 + 回滚演示端点）
├── mvc-server/    Spring MVC(war → Tomcat)：服务端 + admin-console
└── mvc-client/    Spring MVC(war → Tomcat)：客户端，同上
```

每应用两套配置：application-sqlite.yml（默认）/ application-datasource.yml；
README 写明两模式启动与验证步骤；事务演示端点风格 `/demo/order?fail=true`。
