# 设计方案：Linkora 运维控制台 UI/UX v2

状态：**待评审**。上一轮已确立「任务驾驶舱」信息架构（顶部导航 + 待办工单流 + 去卡片化），
本文档在此基础上补全视觉规范、登录页专项与交互设计，作为后续实现的验收依据。

## 1. 设计原则

1. **内容即界面**：无边框化，用留白、字号、分隔线分层；卡片只给可操作对象（客户端）
2. **待办优先**：异常事项永远在首屏 C 位，监控数据退为辅助
3. **动效有目的**：进场用 fadeUp 表达"页面切换"，数字用 count-up 表达"数据更新"；
   一切动效 ≤ 650ms，不做纯装饰动画
4. **反馈必达**：每个操作必须有 loading → 结果（toast）→ 列表刷新三段反馈，绝不静默

## 2. 视觉规范 v2

### 2.1 色彩 token（暗色优先）

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#0B0C12` | 页面画布（带蓝调的深黑） |
| `--raised` / `--raised-2` | `rgba(255,255,255,.03/.06)` | hover 面、轻卡片 |
| `--hair` / `--hair-2` | `rgba(255,255,255,.07/.13)` | 分隔线 / 输入框描边 |
| `--ink` / `--ink-2` / `--ink-3` | `#F2F3F7 / #A6ACBB / #5D6370` | 主 / 次 / 弱文字 |
| `--accent-grad` | `#8B7CF8 → #4CC3F7` | 主按钮、导航下划线、logo、面积图（靛紫→晴蓝） |
| `--accent-border / --accent-ring` | `rgba(139,124,248,.32/.16)` | 强调描边 / 聚焦光圈 |
| `--ok / --warn / --bad` | `#34D399 / #FBBF24 / #FB6F6A` | 语义色，均配同色 glow（0 0 9px 50%） |

规则：语义色只出现在「状态点、工单图标、语义胶囊」三处，禁止大面积铺色；
强调渐变只用于"可点击的主行动"，一个视口内最多一个渐变主按钮。

### 2.2 排印

- 页面大标题 27px/680/字距 -0.025em；区块标题 16.5px/650；正文 13.5px；辅助 12px
- **所有 ID、时间、数字一律等宽字体**（`ui-monospace`）+ tabular-nums
- KPI 数值 38px/700，渐变白→灰，进场 count-up（650ms，ease-out-cubic）

### 2.3 几何与动效 token

- 圆角：工单图标 11px / 输入与按钮 9px / 弹窗 16px / 抽屉直角贴边
- 间距：8px 网格；页面左右 padding 32px；区块间距 34px
- 动效曲线：页面 `cubic-bezier(.22,.8,.35,1) 320ms`；弹层 `cubic-bezier(.3,1.2,.4,1) 200ms`（轻微回弹）

## 3. 登录页专项

### 3.1 布局

居中玻璃卡片（392px，blur 18px + 内高光描边），背后左右两团极光渐变（绿/青，blur 150px）。
卡片内：渐变 logo（56px，投影发光）→ 标题 → 副标题 → token 输入 → 错误行 → 主按钮 → 底部提示。

### 3.2 状态设计

| 状态 | 表现 |
|---|---|
| 默认 | 输入框 placeholder `Bearer Token`，等宽字体，type=password |
| 聚焦 | 描边变 `--accent` + 3px 外圈光晕（rgba 62,207,142,.16） |
| **校验中** | 按钮文字变「验证中…」+ 内联转圈，按钮禁用，防止重复提交 |
| 失败（401） | 错误行红字（"令牌无效或已过期"）+ **卡片水平抖动动画 380ms**；连续失败 2 次后提示"检查 linkora.admin-console.token 配置" |
| 成功 | 卡片淡出上移 → 主界面 fadeUp 进场，KPI count-up 接力，形成"进入"的连贯感 |

### 3.3 细节交互

- 输入框右侧「显示/隐藏」明文切换（eye 图标）
- 回车直接提交；粘贴 token 自动去首尾空格与 `Bearer ` 前缀（容错）
- 底部提示固定文案：「令牌由服务端 linkora.admin-console.token 配置」
- 会话保持：token 存 sessionStorage，关闭标签页即失效（安全默认，不做"记住我"）

## 4. 页面布局规格（保持上一轮结构，补细节）

### 4.1 驾驶舱（默认页）

```
大标题「驾驶舱」+ 一句副标题
─────────────────────────────────────────────
在线 3/5   │  未完成 6   │  死信 2     │  今日发布 10
─────────────────────────────────────────────
需要你处理（N 项）                    进入死信处置 →
  [🔴工单] 死信待处置 · MSG-xxx …    [详情][重放]
  [🟡工单] 自动重试中 · MSG-xxx …    [详情][跳过]
─────────────────────────────────────────────
近 7 日发布量（全宽面积图）      │  最近动态（事件流）
```

- 工单：hover 抬亮背景；图标按严重度发光；操作按钮**常显**（兼顾触屏），
  每行最多 2 个主操作，其余收进「详情」抽屉
- 指标条：手机端 2×2 折行；每格下方 m-sub 提供上下文（如"共 5 个注册客户端"）

### 4.2 消息页

- 筛选：clientId 精确输入 / 类型下拉 / 起始日期，点「查询」或回车生效（输入中不触发请求）
- 列表：行式无边框，messageId 用 accent 色暗示可点；投递摘要列人类可读
- **点击行 → 右侧抽屉**（见 5.3）

### 4.3 死信处置（工单流）

- 客户端下拉（选项带死信计数）；选中后加载该客户端全部死信工单
- 每单：失败原因（等宽）+ 重试次数 + 更新时间；操作：详情 / 重放 / 跳过
- 头部批量动作：批量跳过（带确认）；通用状态变更（独立模态，target 下拉 + reason 必填）
- 停留超过 24h 的死信，工单上加「滞留 xx 小时」warn 胶囊

### 4.4 客户端页

- 轻卡片 2 列（手机 1 列）：在线态带发光文字；未完成/死信非零时数字着色
- 卡内动作：未完成明细（就地展开）、远程指令（面板展开）、断开连接（确认）
- 远程指令面板：PING / QUERY_OUTBOX 按钮；QUERY_OUTBOX 下发后显示轮询态
  「→ 等待回执…（n/15）」，收到结果渲染为只读代码块

## 5. 交互设计（全量清单）

### 5.1 全局

| 触发 | 反馈 |
|---|---|
| `⌘K / Ctrl+K` | 命令面板；↑↓ 选择、回车执行、Esc 关闭、输入即时过滤 |
| `Esc` | 依次关闭：命令面板 → 抽屉 → 弹窗 |
| 轮询刷新（10s） | **有骨架防闪烁**：数据已在显示时静默替换，只有首屏为空才显示骨架；弹窗打开时暂停本轮刷新 |
| 写操作成功 | 成功 toast + 强制刷新当前页数据 |
| 任何请求 401 | 清 token → 回登录页，toast 提示 |
| 请求失败 | 右上错误 toast（bad 色），内容取服务端 `error` 字段 |
| 键盘可达性 | 所有可点元素 focus-visible 光圈（accent 3px） |

### 5.2 点击与查看

| 对象 | 交互 |
|---|---|
| 消息行 | 点击 → 详情抽屉右滑入（280ms 回弹）；遮罩点击 / Esc / 关闭钮退出 |
| 工单「详情」 | 同上，打开对应消息详情抽屉 |
| messageId | 抽屉标题栏内**点击复制**（navigator.clipboard + "已复制" toast） |
| 客户端「未完成明细」 | 就地展开（首次点击才请求），再次点击收起；展开态按钮文字不变、箭头翻转 |
| 客户端「远程指令」 | 指令面板展开；QUERY_OUTBOX 后进入轮询态并显示进度 |
| 面积图数据点 | hover 显示 tooltip（日期 + 条数），圆点放大 |
| 导航页签 | 点击切换页面（fadeUp）；当前页签发光下划线 |

### 5.3 写操作流（二次确认统一范式）

```
点击操作按钮
  → 弹窗：标题（操作名）+ 影响说明（明确状态迁移，如 DEAD_LETTER → RETRYING）
  → reason 输入框（必填，空提交 = warn toast + 聚焦输入框，不关闭弹窗）
  → 点「确认执行」：按钮变「执行中…」+ 禁用（防双击）
  → 成功：弹窗关闭 + 绿 toast（含结果，如"已送达 1 个连接"）+ 列表刷新
  → 失败：弹窗保持打开 + 红 toast（服务端 error 原文）
```

危险级别区分：跳过/断开/停用按钮用红色调；重放/启用用 accent 色调。

### 5.4 加载 / 空态

- 首屏：骨架屏（shimmer 微光，1.3s 循环）
- 空态：居中图标（accent 低透明度）+ 一句话引导（如"死信按客户端隔离存放，先选择要处置的客户端"）
- 驾驶舱无待办：「一切正常 ✓」绿光确认态（运维的正反馈时刻）

### 5.5 响应式（运维也会用手机看）

| 断点 | 行为 |
|---|---|
| ≥1100px | 现行布局 |
| <1100px | 指标条 2×2；双栏（图+流）改单栏；客户端卡 1 列 |
| <720px（手机） | 页签收敛为图标+文字精简；表格横向滚动；工单操作按钮换行常显 |

## 6. 实施清单

| 优先级 | 项 |
|---|---|
| P0 | 登录页全状态（校验中/抖动/明文切换/粘贴容错）、写操作按钮 loading 防双击、messageId 点击复制 |
| P0 | 轮询防闪烁（数据替换不闪骨架）、弹窗打开时暂停轮询 |

| P2 | 亮色主题（token 已就位）、页面切换记忆（刷新后回到当前页签） |

## 7. 验收标准

1. 登录页：五个状态（默认/聚焦/校验中/失败抖动/成功进场）逐一手动走查
2. 写操作：连点确认按钮不产生重复请求；失败弹窗不丢 reason
3. 轮询期间界面无闪烁；弹窗打开 10s 界面无跳变
4. 1440px / 1100px / 375px 三档宽度走查无布局破坏
5. 全部既有 E2E 测试保持绿（UI 改动不触碰 API 层）
