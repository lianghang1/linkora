# 安全设计

## 原则：纯应用层，不依赖 PKI/证书

真实生产环境可能无法满足证书管理要求，安全能力全部在 SDK 功能层实现：

- **不要求任何证书申请或 mTLS 配置**。
- HTTPS 为建议项：客户端保持 JDK 标准证书校验（禁止默认关闭），不要求用户申请证书。
- 内网 HTTP 环境可运行，风险由接入方评估（文档标注）。
- IP 级封禁、WAF、fail2ban 交给宿主已有反向代理层，SDK 提供配合配置说明。

## 认证

| 机制 | 说明 |
|---|---|
| 高熵 token | ≥32 字节随机凭据，服务端预分配，Header 携带；**禁止放入 URL**（避免进入反代/访问日志） |
| HMAC 请求签名 | 时间戳 + nonce + 共享密钥对请求签名；防伪造、防重放、防篡改，SDK 内完成 |
| 凭据轮换 | 可配置双凭据并存窗口，平滑轮换 |
| 存储隔离 | 客户端凭据存储为可插拔接口，避免不必要的明文落盘 |

- `clientId` 必须以认证上下文解析校验，请求体中的 clientId 不可信。
- 签名与凭据比较使用恒定时间比较（`MessageDigest.isEqual`），防时序侧信道。

## 防爆破（SSE 接口暴露于互联网）

1. 高熵 token 使离线/在线爆破在算力上不可行（第一道防线）。
2. 按 `clientId` + 来源 IP 统计认证失败：指数级延迟响应，超阈值锁定并可配置告警。
3. 防枚举：不存在的 clientId 与错误凭据返回统一错误码、统一耗时。
4. 认证失败计数接入指标（第 14 节），异常失败率告警。
5. SSE 建连与上报共用同一认证体系；连接数限制 + 速率限制防资源耗尽。

## 输入与输出防护

- 请求体大小限制（默认可配置）、字段校验、协议版本校验。
- SSE 字段正确编码，业务负载不直接拼接进事件流。
- 日志：关联 messageId/clientId/traceId，不记录完整凭据与未脱敏负载。
- 错误响应不泄露凭据、内部堆栈、敏感数据。
- 重放防护：HMAC 时间戳窗口 + nonce 去重（服务端缓存窗口内 nonce）。
